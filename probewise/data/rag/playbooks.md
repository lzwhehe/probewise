# 处置手册

## P-01 异常登录（suspicious_login）
1. 先确认认证上下文：是否为常用设备、是否完成 MFA、是否使用了不支持 MFA 的旧协议。短时间内出现大量 MFA 推送请求，是凭据已泄露的强信号。
2. 对照用户行为基线和变更工单，排除出差、VPN 出口切换等合理原因。
3. 判定为真实威胁时：先吊销会话、再重置密码并重新注册 MFA；吊销与重置需要账号负责人或值班主管确认，避免误伤正常业务。
4. 判定为误报时：记录合理原因，为同类场景（同一用户 + 同一出口）建立抑制规则候选，经复核后生效。

## P-02 可疑程序执行（malware_execution）
1. 优先查看进程链：程序是否从用户可写目录启动、父进程是否合理、签名是否有效。
2. 查询文件哈希在全网的流行度和情报信誉；只在少数主机出现的未知程序需要重点关注。
3. 沙箱分析成本高、耗时长，只在前面的低成本检查无法定论时使用。
4. 判定为真实威胁时：隔离主机前需确认该主机不承载关键业务；全网封禁哈希和采集取证包可以自动执行。

## P-03 疑似 C2 外联（beaconing）
1. 固定间隔的外联本身不能说明问题，大量软件的遥测、更新检查都是周期性的。
2. 结合域名情报、全网流行度和发起进程判断：只有极少数主机访问、由可疑进程发起的周期外联风险最高。
3. 判定为真实威胁时：在 DNS 和代理层封禁域名，必要时隔离主机，并回溯同一域名的历史访问记录。

## P-04 特权账号变更（privileged_account_change）
1. 先核对变更工单：没有对应工单的特权变更，一律按高风险处理。
2. 关注操作时间、操作者的历史行为和认证方式；凌晨、首次出现、旧协议认证的组合需要立即升级。
3. 判定为真实威胁时：禁用新建的特权账号需要目录服务负责人确认，同时拉取该时段的审计日志。

## P-05 大量数据外传（bulk_upload）
1. 外发流量激增需要结合业务背景判断：备份、素材同步、版本发布都会产生大流量。
2. 重点关注离职或转岗人员、首次出现的上传行为、个人网盘等非公司可控的目的地。
3. 判定为真实威胁时：暂停外部上传权限需要部门负责人确认，同时通知数据防泄漏团队复核已上传内容。

## P-06 办公软件派生脚本（office_child_process）
1. 办公软件派生脚本解释器是钓鱼攻击的常见迹象，但已备案的宏和报表工具也会这样做。
2. 查看进程链和全网流行度：同一模板在大量主机上运行通常是正常业务。
3. 判定为真实威胁时：隔离主机、撤回同源邮件需要人工确认；附件哈希可以自动封禁。

## P-07 网络攻击告警（web_attack）
1. WAF / IDS 告警量大、误报多：大多数误报来自业务系统自己拼接的 SQL 片段、调试参数、内部扫描器和软件下载。先看规则历史和请求路径是否属于本单位业务系统。
2. 判定为误报前必须看过载荷：只要请求里有明确的利用载荷（目录穿越、JNDI、OGNL 表达式、UNION SELECT 等），即使规则历史以误报为主也不能直接关闭。
3. 响应里出现利用成功的迹象（/etc/passwd 内容、表达式计算结果回显、命令执行输出）时立即升级应急响应，并通知资产负责人核查。
4. 判定为攻击尝试时：封禁源 IP 需要值班负责人确认；同一条规则长期以误报为主时，提出「规则 + 路径」白名单建议，复核后才生效。
