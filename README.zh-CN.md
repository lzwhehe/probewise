# ◆ Probewise（中文说明）

**证据驱动的安全告警研判：每一步都挑最值得问的问题，每个判定都附带可以独立验证的证明。**

[在线演示](http://39.105.66.226/probewise/) · [English](README.md)

## 为什么做它

大多数 AI 安全运营 Agent 让大模型同时决定「下一步查什么」和「结论是什么」。模型读错一行日志，或者被工具输出里的文字带偏，结论就会出错，而且事后很难核对。

Probewise 把两件事拆开：

- **模型只负责读**：读取器（规则、Ollama / vLLM 本地模型，或通过 MCP 接入的外部 Agent）把一段工具输出读成固定选项中的一个。
- **控制器负责判**：贝叶斯证据账本按「期望信息增益 ÷ 成本」挑下一项检查，证据够了就停；每个判定都附带证明（先验、每条证据的似然比、后验、SHA-256 哈希链），任何人都可以重算。

## 主要功能

- **LangGraph 状态图**：接收 → 规划 ⇄ 调查 → 判定 → 响应 → 报告，SQLite checkpoint 持久化。
- **按信息增益规划**：每一步计算剩余检查的「比特 / 成本」，沙箱这类昂贵检查只在便宜检查定不了时才用。
- **证据承载式判定**：`probewise verify` 或网页上的「在浏览器中独立验证」，只凭知识库重算哈希链和后验；改动任何一条证据都会被发现。
- **人在回路**：隔离主机、重置凭据、新增抑制规则等动作通过 `interrupt()` 暂停，人工审批后才继续，审批记录写入哈希链。
- **time-travel 反事实**：改写任意一条证据，从它之前的 checkpoint 分叉，控制器重新规划后续调查。
- **稳健模式**：结案至少需要两条同方向的强证据，读取器不可靠时显著降低漏报。
- **RAG 带引用**：BM25 检索处置手册、ATT&CK 说明和历史案例（可选向量重排），报告逐条引用。
- **MCP Server + Agent Skill**：Claude Code 等客户端可以直接研判，也可以只当「读取器」，判定权留在 Probewise。
- **OpenTelemetry GenAI 规范**：`invoke_agent`、`execute_tool` 等 span，可接入 Jaeger、Langfuse。
- **演示不需要任何 key**：18 条合成告警、模拟工具、规则读取器。

## 基准测试（18 个合成场景 × 5 种策略 × 3 档读取噪声，各 10 个随机种子）

- 读取准确时：Probewise 快速模式正确率 77.8%、平均成本 4.56；固定 SOP 正确率 66.7%、成本 7.00。
- 读取器 10% 出错率时：稳健模式把漏报率从 2.8% 降到 0.6%（约 4.7 倍），代价是升级率从 27.8% 升到 41.7%。
- 结论：读取器可靠时用快速模式，本地小模型读取时用稳健模式。场景和似然参数是示意性的，数字用于说明取舍，不代表真实环境的表现。

## 快速开始

```bash
pip install git+https://github.com/lzwhehe/probewise
probewise triage A-004
probewise serve        # Web 控制台 + API
claude mcp add probewise -- probewise mcp
```
